# Run a proof-of-concept experiment

Output: `research/experiments/EXP-NNNN-<slug>/` holding `README.md` (the report, shaped by the template (`research/templates/experiment.md`)), the code that produced its numbers, and `results/` with the raw output. The identifier is the ledger's next experiment counter; the idea must be `triaged`.

1. **Pre-register.** Write the report's hypothesis, success criterion, method and reproduction plan before any code; status `planned`; add the ledger row. Freeze a copy under `results/` with its SHA-256 and UTC time. Research rule 3 requires that frozen copy in a commit before code: verify it against `git show HEAD:<path>` and stop at `planned` if it is absent or differs. The loop makes no git writes; its caller commits between phases. Choose E0 (exact arithmetic or the cost model) or E1 (CPU wall clock). Done when the committed criterion states the numbers and comparisons that mean `validated`, `refuted` and `inconclusive`.
2. **Build the harness.** Baseline and candidate in the same program, same inputs, same machine. Rust: an empty `[workspace]` table in the manifest (its own workspace), `license = "Apache-2.0 OR MIT"`, `publish = false`, `#![forbid(unsafe_code)]`, the SPDX header on every file, `tessera-field` or another crate by path (`../../../crates/<name>`) when the experiment needs the field or the hash; commit the `Cargo.lock` the run produced. Python: `#!/usr/bin/env python3`, the SPDX header, run with `python3 -I`, arbitrary-precision integers for anything exact. Inputs come from a seeded generator (SplitMix64, seed stated). Done when the baseline reproduces a known value: a vector from `spec/vectors/`, the cost model's golden table, or a hand computation written in the report.
3. **Measure** as RFC-0020 does: 3 warm-ups, 10 measured iterations, median, minimum, maximum and coefficient of variation; a coefficient above 3% is flagged and the run repeated. For E0, measuring means computing with the tool and showing the derivation. Record the environment line (CPU, OS, toolchain versions, date). Done when the results table is filled and the raw output is saved under `results/`.
4. **Judge** against the pre-registered criterion and nothing else; list the threats to validity (CPU against GPU, operation counts against wall clock, cache effects, input distribution); verdict. Done when the verdict is one of the three words and the idea's score and status are updated with the reason.
5. **Record.** Experiment status `done: <verdict>`; the idea's status; the ledger; follow-ups naming the next experiment and what an H100 run would settle. `cargo xtask lint` passes.

## Rules of evidence

- A candidate that is faster but produces a different digest is a bug in the experiment, not a result. Every comparison carries a correctness check the candidate must pass.
- Operation counts (E0) are reported as counts; a conversion to time states the throughput assumption beside it.
- The comparison is against the baseline in the harness, never against a paper's number.
- CPU timing has one writer: serialize benchmark processes, record raw samples and reruns, and keep builds and tests idle during measurement. Parallel agents may prepare separate harnesses.
- When the criterion's evidence level is out of reach here, stop at pre-registration, mark the experiment `shelved (E2 needed)`, and record what the H100 protocol must run.
