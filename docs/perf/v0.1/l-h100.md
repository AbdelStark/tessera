# `c_ℓ` on H100: LogUp fraction trees

The per-lookup unit cost of [RFC-0020](../../rfcs/RFC-0020-cost-model.md#measurement-protocol-v01-gate), measured on 2026-11-09 with the microkernel of [#63](https://github.com/AbdelStark/tessera/issues/63). The work is 2^30 lookups into a 2^24-row table ([RFC-0008 'Fraction tree'](../../rfcs/RFC-0008-logup-and-tables.md#fraction-tree)), in two trees:

- **The lookup tree** has 2^30 leaves `(1, α − (k_i + β·v_i))`.
- **The table tree** has 2^24 leaves `(−m_j, α − (k_j + β·v_j))`.

Keys, values and multiplicities come from the counter generator. For each tree the microkernel does three things:

- builds its levels bottom-up in `Fp2`;
- runs its degree-3 level sumchecks of `N_0·D_1 + N_1·D_0 + λ·D_0·D_1` on a transcript, with RFC-0010's labels and messages ([RFC-0010 'Tree levels'](../../rfcs/RFC-0010-proof-schedule.md#tree-levels));
- generates the leaves inside the kernels that read them (the level build and the leaf level's first two rounds), and never stores them.

## Result

| Measurement, per lookup (2^30) | Median | Min | Max | CV |
|---|---|---|---|---|
| Lookup tree, 2^30 leaves | 282.63 ps | 282.24 ps | 282.75 ps | 0.06% |
| Table tree, 2^24 leaves | 14.33 ps | 14.29 ps | 14.50 ps | 0.42% |

**`c_ℓ` = 297.0 ps per lookup**, against an assumed 40 ps: `ρ_ℓ = 7.42`.

Before any run is timed, the benchmark proves each tree with the CPU prover `tessera_sumcheck::prove_trees` on the same generated leaves and transcript, at full size. Every level's messages, the leaf claims and the transcript state that follows are equal.

Evidence level E1 on the target hardware. The environment is that of the [`c_c` report](cc-h100.md).

**Deviation from the protocol.** In a proof, the two trees run in one batch: the table tree joins six levels down, front-padded and weighted by `γ`. Here each tree is proven as a batch of its own, and the two times are added. Batching adds only the padded instance's constant rounds, which need no table work, so the sum is the cost of the batch up to those few host-side terms. The table tree costs 5% of the total. With 2^24 rows over 24 levels it is bound by per-round latency, about 920 ps per row.

### Where the time goes

For a 2^28-leaf lookup tree, from an instrumented run (322.7 ps per lookup), the times are:

| Part | ms |
|---|---|
| Build (leaves generated, levels 27 to 1) | 10.5 |
| Leaf level 27 (27 variables, numerators 1) | 30.3 |
| Level 26 (stored, four tables) | 17.3 |
| Level 25 | 9.1 |
| Level 24 | 5.0 |
| Levels 0–23 | about 14 |

A fraction level costs about 3.5 times a product level of the same size ([`c_π`](pi-h100.md)). Its tables are `Fp2` from the leaves up (`α` is in `Fp2`), and each node evaluation is four `Fp2` products, not one base-field product.

## How far this is from the floor

Counting this algorithm's work per lookup gives a floor near 2 for `ρ_ℓ`:

- **Arithmetic.** About 17 `Fp2` products over all levels, roughly 52 base-field multiplications, which is about 70 ps at the lazy rate measured for `c_c`.
- **Memory.** The stored levels and bound tables move about 80 bytes, which is about 27 ps, partly overlapped.

Together these put the floor of this algorithm on H100 near 80–100 ps, `ρ_ℓ ≈ 2–2.5`. Gruen's trick, which derives one of the three node sums from the claim, would bring it toward 60 ps.

The measured kernel is three to four times above that floor, so there is room to optimize. The levers are Gruen's trick, sums accumulated per `eq_hi` block, delayed reduction as in the CPU kernels (#391), and fewer passes over the leaf level. Even so, the 40 ps assumption needs either a cheaper tree or fewer lookups (`K_lin`, [research/baseline.md](../../../research/baseline.md)).

## Reproduce

```sh
cargo test --release -p tessera-gpu --features gpu --test fraction   # byte-identical to prove_trees
cargo run --release -p tessera-bench --features gpu --example gpu_unit_costs -- l
```

`--lookups-log A` and `--rows-log T` change the tree heights. The tests in `crates/tessera-gpu/tests/fraction.rs` cover heights 1, 2, 3, 5, 9 and 14 with numerators of 1 and with `−m_j`, and the refusal of a workspace made for the other kind of tree.
