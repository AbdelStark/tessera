# Changelog

All notable changes to the verifier release train are recorded here: the crates under `verifier/` and the `tessera-verify` command-line tool. The verifier is versioned independently of the prover (tags `verify-vX.Y.Z`); the two trains are compatible through protocol versions only ([09 §1](../docs/spec/09-release-and-versioning.md#1-what-is-versioned)). The format follows [Keep a Changelog 1.1](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Verifier workspace with the seven `tv-*` crates of RFC-0001 as skeletons, its own lockfile, the same toolchain pin as the prover workspace, a stricter `cargo-deny` policy and `allowlist.toml`, the third-party packages permitted in the trusted base ([#28](https://github.com/AbdelStark/tessera/issues/28)).
- Every verifier crate forbids unsafe code; `tv-core` and `tv-codec` also deny `unwrap`, `expect`, `panic!` and unchecked indexing outside tests (RFC-0019) ([#28](https://github.com/AbdelStark/tessera/issues/28)).
- `tv-core` declares the `test-params` feature, which will accept the `test-small` parameter set; a release build with it fails to compile, so test parameters can never certify a statement (02 §5, RFC-0001) ([#37](https://github.com/AbdelStark/tessera/issues/37)).
- `cargo vet` for the verifier workspace (`supply-chain/`), importing the published audit sets of Mozilla, Google, the Bytecode Alliance and Zcash; every third-party crate must be audited for `safe-to-deploy`. `deny.toml` admits no license exception and no ignored advisory, which `cargo xtask lint` checks ([#50](https://github.com/AbdelStark/tessera/issues/50)).
- `tv-field`, the verifier's own field arithmetic, written from RFC-0002 without reference to `tessera-field`: `Fp` in Montgomery form, a different reduction from the prover's so that a structural bug cannot sit in both; `Fp2 = Fp[X]/(X^2 − 7)` with schoolbook products and inversion through the norm; canonical 8- and 16-byte encodings that reject any coefficient `≥ P`; roots of unity `7^((P − 1)/2^k)`; and the radix-2 NTT with its inverse and coset variants over `Fp` and `Fp2`, which reject a length that is not a power of two or exceeds `2^32`, and a zero coset shift, before touching the values. Every Goldilocks vector in `spec/vectors/field/` passes ([#40](https://github.com/AbdelStark/tessera/issues/40)).
- `tv-testkit`, test support for the verifier crates: a reader for `spec/vectors/` and a seeded SplitMix64 generator, with no third-party dependency, so verifier tests add nothing to the audited graph. `cargo xtask check-isolation` rejects any normal or build edge into it in the verifier's resolved dependency graph ([#40](https://github.com/AbdelStark/tessera/issues/40)).
- `tv-codec`, the verifier's TCE decoders, written from RFC-0003 without reference to `tessera-codec`. Instead of a trait per type and a derive macro, a cursor reads each primitive, takes and releases depth levels explicitly and checks every sequence length against its element's minimum size before reading an element; composite types are combinators over closures. Every error carries its code (`ERR-CODEC-TRUNCATED`, `-NONCANONICAL`, `-LIMIT`, `-MAGIC`, `-VERSION`, `-DIGEST`) and the offset of the check that failed, in the order of checks the crate documentation specifies; a reader that runs out of memory reports `ERR-RES-MEMORY`, and a schema decoder whose element consumes less than its declared minimum `ERR-INTERNAL`, neither of them a fault of the input. A sequence never has room for more elements than the bytes left can hold (INV-TCE-3), and its room grows with the elements decoded, so sequences nested in one another hold memory in proportion to what they have decoded. Decoding rejects bytes left over (INV-TCE-4) and caps nesting at 256 levels. Envelopes open in RFC-0003's order, with a digest function the caller supplies verified before any payload byte is decoded, and the payload decoder is told the schema version found; `DecodeLimits::MESSAGE` and `DecodeLimits::INTEGER_MODEL` are RFC-0003's defaults. Every vector of `spec/vectors/codec/` passes, every check has a test asserting its code and offset, and 1.6 million decodes of seeded random and mutated inputs, through every decoder and the envelope, run without a panic, each accepted input judged by oracles written from RFC-0003 alone: its canonical encoding computed from the value (INV-TCE-2), its limits, and the offset at which each of its prefixes is cut short ([#44](https://github.com/AbdelStark/tessera/issues/44)).
- `tv-testkit` gains a reference BLAKE3 in key-derivation mode, written from the BLAKE3 specification for tests only and checked against every official test vector, so that verifier tests recompute envelope digests without a third-party crate ([#44](https://github.com/AbdelStark/tessera/issues/44)).
- `verifier/fuzz`, cargo-fuzz targets for every decoder (`decode`) and for the envelope (`envelope`), in a workspace of their own with its own nightly pin, so that `libfuzzer-sys` never enters the verifier's dependency graph; `seeds.py` seeds them from `spec/vectors/codec/`, and their oracles re-encode each accepted value from RFC-0003 and measure it against the limits. Its `tests/allocation.rs` caps memory with a counting allocator: hostile lengths allocate nothing, deeply nested hostile sequences stay within a few MiB, and memory too short for honest values is `ERR-RES-MEMORY`. The `fuzz` workflow checks the crate's format, lints and tests, and runs each target for 10 minutes under AddressSanitizer on pull requests that touch the decoders, the fuzz crate or the codec vectors, and on demand ([#44](https://github.com/AbdelStark/tessera/issues/44)).
- `tv-codec` asserts the offset of every case of `spec/vectors/codec/noncanonical.json`, which RFC-0003 'Limits' now fixes; its crate documentation cites the rule in place of the choices it made where the RFC was silent ([#215](https://github.com/AbdelStark/tessera/issues/215)).
