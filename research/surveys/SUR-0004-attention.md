## Synthesis

**Q1: the bound and the sparsity.** What a certificate must prove is fixed by RFC-0005: `T_exp[k] = round(2^16 · exp(−k · scale))` is exactly 0 when `k · scale > 17 ln 2 ≈ 11.78` nats, so a (query, key block) can be skipped without changing one bit of `D` when every score in the block is at least 11.78 nats below `c_q` (E0, primary: RFC-0005 line 72). Both `SoftmaxRow` relations survive: a skipped key has `x_qi ≤ U_qb < c_q` (relation 1's `k ≥ 0` is implied), and the zero of relation 2 lies in an unskipped block because the block holding the maximum has `U_qb ≥ c_q`. Three bound shapes exist in the literature. Quest's per-dimension min/max bound [Tang24] is tight but spends one non-arithmetic `max` per dimension, 128 lookups per (query, 64-key block): two lookups per skipped score, more than the 1 lookup + 1 commitment + 1 leaf (82 ps) a skipped score saves, so it is a loss (E0, this survey). BLASST's rule [YuanJ25] uses the exact block maximum, which inside a proof is itself a max certificate per block, circular. Louver's ball bound [Dehghankar26] `⟨q, c_b⟩ + ρ_b ‖q‖` is the bet the source names: one virtual inner product per (query, block), a committed integer `n_q ≥ ‖q‖` per query (certified once by `n_q² ≥ ‖q‖²`, below 2^52 for scores under 2^21), one `NonNeg` lookup per (query, block) for `c_q − k_0 − ⟨q, c_b⟩ − ρ_b n_q ≥ 0` (the squared form `ρ_b² ‖q‖²` would reach 2^102 and overflow the field), plus one `NonNeg` lookup per key per block for `Σ_j (k_ij − c_bj)² ≤ ρ_b²`, amortized over the `S/2` queries. The certificate costs about 50–100 ps per skipped block of 64 (one lookup plus `d_head` virtual multiplications of glue) against 5.2 ns saved (E0, this survey), so the gain is set almost entirely by the fraction of blocks the bound certifies. Soundness needs only validity of `c_b`, `ρ_b` and the bound, never their uniqueness (a loose bound skips less); this keeps SP-3 intact, and value-neutrality keeps the statement identical, which is what separates it from the hollow-proof class [Gong26]. Two things are unmeasured and decide everything: (a) the *hard* sparsity, the fraction of 64-key blocks of Llama-3.1 attention whose true maximum is below `c_q − 11.78` at 16K–128K; every published number is attention mass or top-k recall ([Jiang24] 96.8% mass in the top 4,096 of 131,072 columns; [Liu24] 89% in the top 1,000 of 100,000; [Zhu25] 90% mass in 3–8% of tokens at 96K), which says the tail is thin but not that it rounds to zero at `σ = 16`; (b) the looseness of the ball bound on RoPE-rotated blocks (adjacent positions rotate differently in the high-frequency dimensions, inflating `ρ_b`). BLASST's sparsity-against-λ data (23% at 4K to 75% at 64K at one λ) is the nearest proxy and runs the right way with context, but its λ is an accuracy tolerance, far above `2^−17`. The sensitivity table gives the prize once (a) and (b) are known: skipping 50 / 75 / 90% of blocks takes `μ(16K)` from 35.1 to 20.5 / 13.5 / 9.5 and `μ(128K)` from 171.4 to 85.5 / 44.1 / 20.6 (E0, primary: `cost_model.py --set scores_per_token_per_ctx`), because `stream` scales with `A` too. Two security costs must be priced in the idea note: the skip mask is derived from activations, so it is secret-class (05 §3); the proof's lookup and leaf counts then leak attention statistics unless padded to a public per-layer budget, which turns a measured gain into a worst-case one; and the causal selector `C(q, i)` stops being public, so the sumcheck over `V_q` needs a committed selector (one commitment per (query, block), about 0.5 ps per score). Rule 6 of the knowledge base (no model weights under `research/`) means the measurement (a) must be run outside the knowledge base and only its statistics recorded.

**Q2: sharing or replacing exp lookups.** Settled, and negative. Every proof system read spends at least one lookup per exp: zkLLM five ([SLZ24]), Hao et al. one per 12-bit digit ([Hao24]), zkGPT one on a dense table ([Qu25]), ZK-DeepSeek one plus a shift ([Wang25]), NanoZK one anchor plus interpolation ([Wang26b]). The polynomial route ([Kim21]: `L(p) >> z`) replaces one lookup by a range check on `p` and a requantization of the shift, two lookups; the separation principle [Jo26] says the per-lookup cost cannot see exp's structure anyway. Tables are already shared: RFC-0008 runs one fraction tree per table across all layers, heads and tokens and RFC-0006 shares identical definitions. "One lookup per block with a residual" has no exact instantiation, since each `e_qi` is committed and feeds `PV`; a block-level exp is a change of `D` (Q4). This confirms RFC-0008 and RFC-0009 Alternatives 1–2; the count is the only lever, which is Q1 and Q4.

**Q3: cheaper max certificates.** Contested only for lack of sources. No paper studies a proof of "some entry is zero" other than the grand product; the one cost comparison ([Jolt26], secondary) places the GKR product tree at the cheap end and trades prover time for proof size. The alternatives examined here fail on cost: a one-hot or a per-row LogUp membership (`(q, 0) ∈ {(q, k_qi)}`) costs a commitment or a fraction-tree leaf per score (30–40 ps against 12 ps), the same verdict as RFC-0009 Alternative 3; folding a zero flag into the `Exp` table value contaminates `PV`; the sum `s_q ≥ 2^σ` is implied by, not equivalent to, a zero key. Two implementation levers remain, both second-order because `c_π` is at most 7.5% of `μ`: the keys are base-field integers, so the leaf levels of the product tree can run in the base field with only the random combination in `Fp2`, which is worth at most the −3.5% / −3.7% of `c_π` halved (E0, primary); and the first product level reads the same virtual `k_qi` as the `Exp` lookup's first fraction-tree level, so the two can share a pass (moves `regen`/`stream`, not `c_π`, and RFC-0010 may already stack them). The 12 ps itself is an assumption until RFC-0020. A certified-skipping design (Q1) amortizes nothing on `c_π` per remaining score but removes the leaves of skipped scores along with their lookups.

**Q4: a proof-aware `D` in bounded mode.** Three production shapes already bound the per-query key count: Gemma 3 (5:1 local layers, 1,024-token windows, "minimal" perplexity impact [Gemma25]) gives `A_eff/A` = 0.27 at 16K and 0.18 at 128K; Llama 4 (3 of 4 layers chunked at 8,192 [HF26]) gives 0.63 and 0.30; DeepSeek V3.2's DSA (top-2,048 [DeepSeek25], [vLLM25]) gives about 0.03 for the main attention plus the indexer's scores and a top-k certificate (E0, this survey). For these models `Û` is unaffected, because `D` is the model. For the Llama-3.1-405B target, the question is the cost of a retrofit: MoBA's Llama-3.1-8B continued pretraining (100B tokens) lands within 0.003 of its dense twin on RULER-128K at 62.5% sparsity [Lu25]; SeerAttention's frozen-weight gate loses 0.4 RULER points at about 85% sparsity at 128K [Gao25]; the Sparse Frontier shows training-free methods need a 1/10 budget at 16K for 0.2 relative error and that multi-needle tasks break first [Nawrot25]. None reports what `Û` measures, bits per token of the deployment's outputs unexplained by `D`; the closest are MoBA's loss-curve fits (a gap of about 0.05–0.08 nats per trailing token at the scales shown) and Tactic's unlabelled KL plot. A proof-aware `D` therefore has an unmeasured `Û` and, for retrofits, a training cost that leaves "unmodified deployment" behind; RFC-0005's fidelity gate (`Û ≤ 0.1` bits/token target, source §9 problem 4) is the right yardstick and nothing in the literature meets or fails it yet. Jo26 applies here too: a gate or indexer is one more non-arithmetic op per (query, block), 1/64 of the dense count, so the count argument favors block-level over token-level selection.

**Against the RFCs.** Confirms RFC-0008 (one dense table), RFC-0009 Alternatives 1–3 and Lemma 5 (nothing cheaper with a uniqueness lemma), and RFC-0005's `σ = 16` as the parameter that makes certified skipping exact. Contradicts nothing. Opens one design question for RFC-0009/RFC-0010 (a committed selector and a skip certificate per (query, block)) and one for RFC-0013 (padding the skip count).

## Candidate ideas

- **Certified block skipping with an integer ball bound** ([Dehghankar26] shape, source §9 bet 1b): per (query, 64-key block) prove `⟨q, c_b⟩ + ρ_b n_q ≤ c_q − k_0` with `k_0 = ⌈17 ln 2 / scale⌉` and a per-query `n_q ≥ ‖q‖`, one `NonNeg` lookup per (query, block) plus an amortized radius lookup per key; moves `A` and `stream`; −41.7% / −50.1% of `μ` at 16K / 128K if half the blocks skip, −61.7% / −74.3% at three quarters (E0); first killer: the measured fraction of blocks that clear 11.78 nats under the ball bound (RoPE inflates `ρ_b`), then the zero-knowledge padding of the skip count.
- **Hard-sparsity measurement** (prerequisite experiment, E1): on Llama-3.1-8B (and 70B if feasible) at 16K / 64K / 128K, the fraction of scores and of 64-key blocks with `c_q − x_qi > 11.78` nats, per layer and head, and the same fraction under the ball bound; run outside `research/` (rule 6) and record statistics only; killer: hard sparsity below about 30% at 16K makes the lever a 128K-only story.
- **Committed causal selector** for skipping: replace the public `C(q, i)` by a committed block mask at one commitment per (query, block), about 0.5 ps per score (E0); killer: it must stay zero-knowledge, so the mask's weight must be padded to a public bound per layer.
- **Base-field leaf levels of the `SoftmaxRow` product tree**: keys are base-field integers, so run the first levels in `Fp` and enter `Fp2` only at the random combination; moves `c_π`; at most −3.5% / −3.7% at 16K / 128K (E0); killer: the 12 ps assumption may already be a base-field figure (RFC-0020 measures first).
- **Share the first product-tree pass with the `Exp` fraction tree's first level** (both read `k_qi`): moves `regen`/`stream`, not `c_π`; killer: RFC-0010 may already stack them in one stage.
- **Proof-aware `D` shapes for bounded mode**: Gemma-3 shape `A_eff/A` 0.27 / 0.18, Llama-4 shape 0.63 / 0.30, DSA shape about 0.03 plus indexer at 16K / 128K (E0); killer: `Û` per token unmeasured for any Llama-3.1 retrofit, and a retrofit needs about 100B tokens of training [Lu25].
- No seed from [SLZ24], [Hao24], [Qu25], [Wang25], [Kim21], [Wang26b]: each spends at least as many lookups per exp as Tessera's one, and [Jo26] says table structure cannot lower the per-lookup cost.
- No new seed from [Lagrange26d]: its approximate shifted-exp relation does not supply Tessera's required exact upstream uniqueness, and one Exp value lookup still carries range/zero/row-normalization work; no same-statement marginal cost was measured. A missing max certificate in a different accepted relation is not a measured reduction in `c_π`.
- No seed from [Tang24]: its per-dimension bound costs two lookups per skipped score, more than it saves.
- No seed from [Gong26], [Chen26], [Liang26]: a caveat, a TEE design and an abstract without numbers.

## Primary-code refresh, 2026-10-19

Scope: this closes the code-inspection part of the DeepProve retrieval task, not the full-paper task or all four standing survey questions. The official repository's complete recursive Git tree and selected raw sources were fetched read-only at `master` commit `9d1a53e2ef49ffa2c902b8689cd3c58057a4e662`. Downloaded files were checked against that tree's Git blob hashes. No third-party code, model, test or benchmark was executed. The PDF block described above remains; no source comment is credited as a protocol proof.

**Max versus advice.** `Softmax::calculate_shift_data` first computes a row maximum for numerical stability, then floating log-sum-exp of the scaled differences, masks sentinel entries, and rounds this into a per-row shift. Integer evaluation multiplies the input by a fixed-point multiplier, subtracts that shift, right-shifts with its rounding convention and applies the Exp table. The shift is committed witness data. `SoftmaxCtx::verify_internal` routes through the generic lookup verifier, whose linking sumcheck connects shifted/decomposed lookup inputs to the original tensor and whose PCS claims open the per-row shift. No distinct max-membership/zero-key/product-tree certificate appears in this inspected Softmax verification path. This is an observation about that path, not a claim that every DeepProve operation lacks comparisons or that its intended approximate relation is unsound. [Lagrange26d]

**Exp, ranges and cost scope.** The current `LookupOp::chunking_info` supplies exactly one value chunk; additional value chunks are supported only for requantization. Exp is a negative-input, two-column table with one rounded/clamped exponential output per key; right-shift chunks use 16-bit ShiftCheck, high chunks use ZeroCheck, and a further ShiftCheck lookup is added per row for normalization. The Exp table width and input/output scales are chosen from the maximum context, quantization width, input scaling and an error calculation. This is not the older `softmax.md` description of Goldilocks, fixed 24-fractional-bit inputs and two 8-bit exp limbs: that document is useful history but does not describe these current constructors or the README's HyperKZG/BN254 benchmark configuration. One Exp value chunk alone is not a complete per-score lookup/commitment cost. No measured saving in `c_ℓ` or `c_π`, and no certified hard-zero block-skipping rate, follows from this source read. [Lagrange26d], [Lagrange26b]

**Normalization range qualification.** The comments describe a row sum near `theta` with error `E`. The actual witness formula is `z = (65535 − 2E) + (theta + E) − sum`, and `compute_norm_eval` uses the same offset. The associated ShiftCheck table is the identity over `[0,65535]`. Under a valid integer lift, this membership alone gives `theta − E <= sum <= theta − E + 65535`, not automatically `theta − E <= sum <= theta + E`. The inspected generic linkage and global LogUp checks do not themselves add a second bound narrowing that interval to width `2E`. This is a conditional algebraic/code observation and an outstanding review obligation, not an executed forged proof or a whole-system vulnerability conclusion: full field-range, all-layer and PCS/transcript soundness were not audited here. In particular, the source's error-bound comments are not sufficient evidence to credit the intended two-sided bound. The actual global verifier does check nonzero lookup denominators, aggregate numerators equal zero and accumulated PCS openings; this note does not mistake a single GKR subclaim for final lookup acceptance. [Lagrange26d]

**Implementation preconditions and quantized-model effects.** The inspected evaluation supports ranks 2–4; its mask extraction uses the first head/batch, so it assumes the same sentinel mask across heads/batches. The attention-mask evaluator treats square prefill and single-query cached shapes, and the post-quantization transform requires an AttentionMask immediately before Softmax and installs the chosen negative-infinity sentinel. The shift-consistency property test explicitly excludes valid logits equal to that sentinel; its existence is test intent, not a test run here. Quantization guards fixed-point intermediate width plus 24 bits at at most 63, requires a positive right shift, and reserves output headroom as a function of maximum context. These implementation conditions are not a proof of Goldilocks no-wrap or Tessera's Lemma 0.

The current default is 12-bit symmetric integer tensors with clipping/round-to-even; representative calibration data sets the scale. Shift witness generation and table setup still contain floating calculations. Optional `--accuracy` mode is described as outlier smoothing/per-tensor tracking for GPT-2 and Gemma 3, with the above-99.6% GPT-2 cosine claim; the detailed README says Llama 2 accuracy mode falls back to default quantization. These statements neither certify the floating model's exact token trace nor measure the bits per token Tessera's `Û` needs. Adopting a different quantized/approximate Softmax would change `D`; eliminating an exact certificate without an exact uniqueness lemma would fail Tessera's SP-3 gate. No new candidate seed or model repricing is licensed. [Lagrange26d], [Lagrange26b]
