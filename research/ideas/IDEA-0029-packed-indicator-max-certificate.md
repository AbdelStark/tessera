## Mechanism

Notation as [RFC-0009 `SoftmaxRow`](../../docs/rfcs/RFC-0009-gadgets.md#softmaxrow): query row `q`, valid positions `i ∈ V_q` (public causal selector), virtual scores `x_qi` with `|x| < 2^21` ([RFC-0005 'Integer semantics'](../../docs/rfcs/RFC-0005-integer-model.md#integer-semantics)), row maximum `c_q`, keys `k_qi = c_q − x_qi`, `σ = 16`, `Exp[k] = round(2^σ · exp(−k · scale))` so `Exp[0] = 2^σ` and every `Exp[k] ≤ 2^σ`, `v_id` INT8, `d_head = 128`, `S ≤ 2^17`. New public parameter: the shift `m = 23`.

1. **Table.** `Exp { key_bits, σ, scale }` gains a zero marker and the shift: `Exp' { key_bits, σ, scale, zero_marker = true, m }` with value `f(k) = 2^m · Exp[k] + [k = 0]` for `k ∈ [0, 2^key_bits)`. Integer-only generator; `f(k) < 2^{m+σ} + 1 ≤ 2^39 + 1`, a 40-bit value in place of the 17-bit `e`. The structured evaluation of [RFC-0008](../../docs/rfcs/RFC-0008-logup-and-tables.md#structured-evaluation) becomes `f̃(ρ) = 2^m · Ẽxp(ρ) + eq(ρ, 0)`: one `O(n)` term added to the existing piecewise form. `TableSpec.digest` changes (new piece parameters).

2. **Per score, unchanged count.** Lookup `(k_qi, f_qi) ∈ Exp'` for every `i ∈ V_q`, with the virtual key `k_qi = c_q − x_qi` and the committed value `f_qi`. Relation 2 of `SoftmaxRow` (the product tree `Π_i k_qi = 0`, one leaf per score, the whole `SoftmaxRow` forest and its [RFC-0010 'Tree levels'](../../docs/rfcs/RFC-0010-proof-schedule.md#tree-levels) stage) is deleted. Per score: 1 lookup, 1 commitment, 0 product leaves.

3. **Per row `q` (per query head): the zero count.** Virtual row sum `F_q := Σ_{i ∈ V_q} f_qi` (exactly the shape of today's virtual `s_q`, through the public selector). Committed: `n_q`. Virtual: `s_q := (F_q − n_q) · 2^{−m}` (a public field constant). Relations: lookup `n_q − 1 ∈ Range{17}` (so `n_q ∈ [1, 2^17]`); `NonNeg(s_q, 34)` (RFC-0009: 1 committed limb, 2 lookups; pins the virtual `s_q` to a true integer in `[0, 2^34)`). Lemma 6's reciprocal bracket uses this `s_q` unchanged. Per row: 2 commitments (`n_q`, one limb), 3 lookups.

4. **Attention output: the `PV` decontamination.** The sumcheck of RFC-0005's `o = R_q · Σ_i e_qi v_i` runs over `f` instead of `e`: `o'_qd := Σ_{i ∈ V_q} f_qi · v_id` (virtual) `= 2^m · o_qd + c_qd` with `o_qd := Σ_i Exp[k_qi] v_id` the true attention integer and `c_qd := Σ_{i : k_qi = 0} v_id` the tie contamination. Committed: `c_qd` for `d < 128`. Virtual: `o_qd := (o'_qd − c_qd) · 2^{−m}`. Relations: lookup `c_qd + 2^{m−1} ∈ Range{m}`; `NonNeg(o_qd + 2^37, 38)` (1 committed limb, 2 lookups). `o_qd` then flows into `o = R_q · o_qd` and the O-projection requant exactly as today. Per `d`: 2 commitments, 3 lookups; per row 256 commitments, 384 lookups. At `S > 2^14` each row's `o'` is split into chunks of 2^14 keys with one `(c, limb)` pair per chunk and `o_qd = Σ_chunks`; `F_q` needs no chunking (`F_q < 2^57`).
   *Why the second `NonNeg` is not optional (the generation pass omitted it, 131 + 131 per row).* Without it `o_qd` is pinned only through the requant of `o = R_q · o_qd`. Shift `c'_qd = c_qd ∓ 2^22` (inside `Range{23}` for every honest `c_qd`, `|c_qd| ≤ 2^21`): then `o'_qd − c'_qd = 2^m o_qd ± 2^22`, so `o_qd' = o_qd ± 1/2` in the field and `o = R_q o_qd ± R_q / 2`. Whenever `R_q = floor(2^{2σ} / s_q)` is even (`s_q = 2^16`, `R_q = 2^16`, the common unsaturated row), that is an in-range integer differing from the honest `o`, and the requant's range table accepts it: a second passing witness upstream of the logits (SP-3). This is exactly SUR-0004 Q3's "contaminates `PV`" objection, made precise; the `NonNeg` on `o_qd` closes it.

5. **Lemma 5″ (statement).** With `|x_qi| < 2^21`, `v` INT8, `σ = 16`, `m = 23`, chunks of at most 2^14 keys, relations (2)–(4) hold iff `c_q = max_{i ∈ V_q} x_qi`, `f_qi = Exp'[c_q − x_qi]`, `n_q = #{i : x_qi = c_q}`, `s_q = Σ_i Exp[k_qi]`, `c_qd = Σ_{i : k_qi = 0} v_id` and `o_qd = Σ_i Exp[k_qi] v_id`, each with exactly one passing witness. Proof sketch, every step reducing to RFC-0009 Lemma 0 (every compared integer below 2^62):
   - The lookup forces each `k_qi` into `[0, 2^key_bits)` (so `c_q ≥ x_qi`) and pins `f_qi = f(k_qi)`; `F_q` is therefore the true integer `Σ_i f(k_qi) = 2^m Σ_i Exp[k_qi] + #{i : k_qi = 0} < 2^17 · 2^40 = 2^57`.
   - `NonNeg(s_q, 34)` pins the virtual `s_q` to an integer in `[0, 2^34)` (Lemma 3 applies to a virtual field element: Lemma 2's argument shows `s_q ≡ v_0 + 2^21 v_1 (mod P)` with the right side a small integer), and `n_q ∈ [1, 2^17]`. The field identity `F_q = 2^m s_q + n_q` has every term below `2^58`, so it is an integer identity; since `0 < n_q ≤ 2^17 < 2^m` and `#{i : k_qi = 0} ≤ |V_q| ≤ 2^17 < 2^m`, the Euclidean decomposition by `2^m` is unique: `s_q = Σ_i Exp[k_qi]` and `n_q = #{i : k_qi = 0}`.
   - `n_q ≥ 1` yields some `k_qi = 0`, hence `c_q = x_qi ≤ max ≤ c_q`: `c_q` is the maximum (relation 1's `c_q ≥ x_qi` gives the other direction). Ties give `n_q ≥ 2` and nothing else changes.
   - For each `d` and chunk: `o'` is a true integer (every `f_qi` and `v_id` pinned), `|o'| ≤ 2^14 · 2^7 · 2^40 = 2^61`; `NonNeg(o_qd + 2^37, 38)` pins `o_qd ∈ [−2^37, 2^37)` (the honest value satisfies `|Σ Exp[k] v| ≤ 2^14 · 2^16 · 2^7 = 2^37`); `c_qd ∈ [−2^22, 2^22)` by its lookup. The identity `o' = 2^m o_qd + c_qd` has every term below `2^61`, so it is an integer identity, and with `|c_qd| < 2^{m−1}` the centered residue of `o'` modulo `2^m` fixes `c_qd` and then `o_qd` uniquely; the honest `|c_qd| ≤ 2^7 · 2^14 = 2^21 < 2^22` passes.
   Padded positions are excluded by the public selector (the sums run over `V_q`), so issue #247's padded-leaf rule becomes moot for `SoftmaxRow`: there is no leaf.

6. **Vocabulary.** The same marker on `Exp_T` removes `InverseCdf`'s `vocab` product leaves per output token ([RFC-0009 'Summary of costs'](../../docs/rfcs/RFC-0009-gadgets.md#summary-of-costs)); `Z = Σ_v e_v` is recovered as `s_q` is, and there is no `PV` term, so the vocabulary case costs 2 commitments and 3 lookups per output token.

## Why it could work

- **The counts (E0, primary, own count).** Per (row, head), `S ≤ 16K`: `n_q` (1) + `s_q` limb (1) + per `d < 128`: `c_qd` (1) + `o_qd` limb (1) = 258 commitments; lookups `n_q`, two `s_q` limbs, and per `d`: `c_qd`, two `o_qd` limbs = 3 + 384 = 387. At 128K with 8 chunks: 2 + 8 · 256 = 2,050 commitments, 3 + 8 · 384 = 3,075 lookups. Per token (16,128 (row, head) pairs per token, `A = heads × layers / 2 = 8,064` in `cost_model.py`): +4,161,024 commitments and +6,241,536 lookups at ≤ 16K (27,740,160 → 31,901,184 and 33,981,696); at 128K +33,062,400 and +49,593,600 (→ 60,802,560 and 77,333,760). At `counted` unit costs (94 + 101 ps, [EXP-0002](../experiments/EXP-0002-commit-cost-calibration/README.md), [SUR-0002](../surveys/SUR-0002-lookups.md), E0 fitted to E1) the additions cost 63.3 ns per row, against the forest's `S/2` leaves per row at `c_π` 73 ps (E0 fitted to E1, EXP-0006): 123.7 ps per score at 1K, 30.9 at 4K, 7.7 at 16K and 7.7 at 128K. Break-even context `S = 2 · 63.3 ns / c_π`: about 1.7K at 73 ps, 3.0K at 41.8 ps (EXP-0008), 10.6K at the `corrected` 12 ps (E0).
- **The integer bounds (E0, primary: [RFC-0005 'Integer semantics'](../../docs/rfcs/RFC-0005-integer-model.md#integer-semantics), read).** `|x| < 2^21`, keys `≤ 2^22`, `s_q < 2^{σ+17} = 2^33`, `v` INT8, `o = R_q · Σ_i e_qi v_i`, and `e_qi` is consumed nowhere else, so every bound of Lemma 5″ (`F_q < 2^57`, `|o'_chunk| ≤ 2^61`, `2^m s_q < 2^57`, `2^m o_qd < 2^60`) sits inside Lemma 0's ±2^62 margin.
- **The verifier's table cost (E0, primary: [RFC-0008 'Structured evaluation'](../../docs/rfcs/RFC-0008-logup-and-tables.md#structured-evaluation)).** Any dense core up to 2^24 explicit values is admitted and `eq(ρ, 0)` is `O(n)`, so `f̃(ρ)` costs the verifier one extra `O(n)` term; `Range { bits }` and `NonNeg` are existing kinds.
- **A wider value column is free for LogUp (E1, primary, other hardware).** [YZL26] (SUR-0010 finding 4; DeepProve, 32 CPU threads): B8 → B16 tables leave the LogUp-GKR prover unchanged at a fixed lookup count; here the table's row count is unchanged and only the value width grows, which enters LogUp as one `β · value` term per leaf ([Hab22], [PH23], primary). The lookup count per score is unchanged.
- **Cost model (E0 over `counted` unit costs).** Δμ +4.1% / −7.7% / −17.0% / −18.7% at 1K / 4K / 16K / 128K (table below); against the post-EXP-0008 baseline (`leaf_ps = 41.8`: 16.8 / 28.1 / 72.2 / 340.0) +6.5% / −1.8% / −9.6% / −10.7%; against EXP-0006's counted floor (`leaf_ps = 45`: 16.8 / 28.3 / 72.9 / 343.4) +6.5% / −2.5% / −10.4% / −11.6%; under `corrected` (`c_π` 12 ps) +5.2% / −0.3% / −5.4% / −5.7%; `bytes_per_leaf = 16` adds −1.6% at 16K (conditional).
- **Against [IDEA-0020](IDEA-0020-argmax-read-max-certificate.md) (E0, both notes' own counts).** 258 commitments and 387 lookups per row here against 384 commitments, 136 LogUp leaves and 1,152 degree-≤3 sumcheck terms there; no committed-table LogUp kind, no one-hot chunks, no tie-break table, no causal check, no cross-layer key-distinctness clause; the uniqueness argument reduces to two Euclidean decompositions over range-checked integers. The 16K gain is −17.0% against −16.1% (counted); the break-even is 1.7K against 1.3K because the per-row cost is 63.3 ns against about 46 ns.
- **Precedent inside the design (primary).** LogUp over committed values against a public table whose value column packs two quantities is [RFC-0008](../../docs/rfcs/RFC-0008-logup-and-tables.md)'s own relation ([Hab22], [PH23]) with [RFC-0009 `Requant1`](../../docs/rfcs/RFC-0009-gadgets.md#requant1)'s `pack(c, z) = (z + 2^{b−1}) + 2^b · c`; the `NonNeg` limb pattern (Lemma 3) is reused unchanged.

## Kill criterion

(1) The exhaustive check at toy parameters (test field F65537, `σ = 2`, `m = 4`, rows of 3–4 scores, all assignments of `(c, n, s-limb, c_d, o_d-limb)`) finds a second passing witness for any row, including all-tied rows and rows whose maximum is at the sink or the diagonal, or an out-of-range `(n, s)`, `c_d` or `o_d` escapes the range tables into a passing `o`; or the checker shows that no choice of `m` and limb widths pins `o_qd` within 2 commitments and 3 lookups per `d`. (2) In one harness the per-row additions (258 element commits + 387 LogUp leaves) cost more than the forest's `S/2` leaves at 4K (more than about 2,048 × 18.4 ns ≈ 38 µs per row on the M4 Max scale, EXP-0008's measured leaf), moving the break-even above 4K and the 16K gain below IDEA-0020's. (3) RFC-0005's `e_qi` is found to be consumed somewhere other than `s_q` and `Σ e v` (read today: it is not), which would need a per-score `e`. (4) The 40-bit value column costs the design a small-value commitment (NG-5, IDEA-0005) worth more than this saves.

## Cheapest experiment
