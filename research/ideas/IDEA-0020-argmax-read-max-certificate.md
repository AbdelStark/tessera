## Mechanism

**Setting** ([RFC-0005 'Integer semantics'](../../docs/rfcs/RFC-0005-integer-model.md#integer-semantics), [RFC-0006 lowering](../../docs/rfcs/RFC-0006-compiler-ir.md), both read). The scores are `x_qi = Σ_j q_j k_ij` over `d_head = 128`, where `q` and `k` are the RoPE outputs requantized to INT8 (`Rotate`, then `Requant`), hence committed tensors per layer (the `Requant` output is committed advice), `k` per KV head shared by the 16 query heads of its GQA group; `|x| < 2^21`. Today's `SoftmaxRow` (RFC-0009) commits `c_q`, looks up `(k_qi, e_qi) ∈ Exp` for every valid `i` (relation 1) and proves `Π_{i ∈ V_q} k_qi = 0` by one product tree per row (relation 2): one leaf per score, which under the `counted` profile is the single most expensive thing the proof does per score after the lookup and the commitment.

The idea replaces relation 2 by three per-row relations and changes relation 1's key. Per (query row `q`, query head `h`) in a layer, with `S` the context (a power of two after padding) and `C` the number of index chunks (`C = 2` up to 16K, `C = 3` at 128K; a tuning knob, see 'Expected gain'):

- **(a) Index.** The prover commits the argmax position `j_q` as `C` one-hot chunks `oh_c ∈ {0,1}^{S^{1/C}}` (`2 × 128` entries at 16K, `3 × 64` at 128K). Relations: booleanity zerocheck `oh_c[i'] · (oh_c[i'] − 1) = 0` (degree 2, degree 3 with `eq`) and `Σ_{i'} oh_c[i'] = 1` per chunk. The position `j_q = Σ_c S^{(C−1−c)/C} · Σ_{i'} i' · oh_c[i']` is virtual and linear in the chunks; it is never committed.
- **(b) Read.** The prover commits `Kread_{q,d} = k^{rot}_{j_q, d}` (`d_head = 128` values per row) and proves it by LogUp membership of the tuples `(j_q · 128 + d, Kread_{q,d})` in the table `{(i · 128 + d, k^{rot}_{i,d})}_{i < S, d < 128}` of that layer's KV head, with committed multiplicities `m_i`, one per key position `i` (every reader of position `i` reads all 128 `d`, so the table's multiplicity `m(i, d) = m(i)` is virtual in `d`), counting the 16 query heads of the group together. The key `j_q · 128 + d` is virtual and linear in the chunks. The table's key column `i · 128 + d` is the index itself, a public multilinear; the table polynomial at the fraction tree's final point `r` is `idx̃(r) + β · k̃^{rot}(r)`, one more claim on an already committed and already opened stacked tensor (`k^{rot}` is `Requant` advice), batched as [RFC-0010 'Batching within a stage'](../../docs/rfcs/RFC-0010-proof-schedule.md#batching-within-a-stage) batches claims. The 1,008 table instances per proof (126 layers × 8 KV heads) are stacked over layers and batched over KV heads in one stage, so they share one final point.
- **(c) Existence and causality.** Zerocheck `c_q − Σ_d q_{q,d} · Kread_{q,d} = 0` over rows (degree 2, `S × 128` terms per (layer, head)); and the causal bound `j_q ≤ q`, as the zerocheck of the virtual `lt_q(q) = [q < j_q]` defined in (d) (a prover that points at a future key would otherwise certify the maximum over keys the row never sees).
- **(d) Tie-break, folded into the lookup key.** Relation 1 becomes `(key'_qi, e_qi) ∈ Exp2` with `key'_qi = 2 · k_qi − lt_q(i)`, `k_qi = c_q − x_qi` virtual as today and `lt_q(i) = [i < j_q]` virtual: with `i = (i_1, …, i_C)` in chunk digits, `lt(i, j) = lt_1 + eq_1 · lt_2 + eq_1 · eq_2 · lt_3 + …`, where `lt_c(i_c) = Σ_{i'} oh_c[i'] · [i_c < i']` and `eq_c(i_c) = oh_c[i_c]`, so `lt_q(i)` has degree `C` in the committed chunks (`≤ 3`, plus one for the public `eq`: inside RFC-0014's `d ≤ 7`). The verifier obtains `l̃t_q` at the `Exp2` fraction tree's final point by one degree-`C + 1` sumcheck of `S × C · S^{1/C}` terms per (layer, head), using the public multilinears `L̃T_c(r_c, i') = Σ_{i_c < i'} eq(r_c, i_c)`. The table `Exp2 { key_bits, σ, scale }` is `Exp2[key'] = Exp[⌈key'/2⌉]` over `key' ∈ [0, 2^{key_bits+1})`: twice the rows of `Exp`, still one piecewise table whose value depends on `key' >> 1` only, so RFC-0008's structured evaluation applies unchanged. Every score still costs exactly one lookup and one commitment (`e_qi`).

**Lemma 5′ (argmax-read certificate).** Relations (a)–(d), with `q_{q,·}` and `k^{rot}` true INT8 integers (RFC-0005) and `|x_qi| < 2^21`, hold iff `c_q = max_{i ∈ V_q} x_qi`, `j_q = min argmax_{i ∈ V_q} x_qi`, and `e_qi = Exp[c_q − x_qi]` for every `i ∈ V_q`. Proof. (a) Booleanity and sum-one leave exactly one non-zero entry per chunk (RFC-0009 Lemma 8's argument), so the digits define exactly one `j_q ∈ [0, S)`, and `lt_q(i) ∈ {0, 1}` is the lexicographic, hence integer, comparison `[i < j_q]`. (b) The table's keys `i · 128 + d` are distinct, so LogUp membership (RFC-0008, error `(N + T)/|Fp2|` over `α`, with `β` fixed after `Kread`, `k^{rot}` and `m` are committed) forces `Kread_{q,d} = k^{rot}_{j_q, d}` for every `d`: an INT8 true integer. (c) Then `c_q = Σ_d q_{q,d} · Kread_{q,d} = x_{q, j_q}` is a true integer with `|c_q| < 2^21`, and `lt_q(q) = 0` gives `j_q ≤ q`, so `j_q ∈ V_q`. (d) Relation 1′ forces `key'_qi` to be an integer in `[0, 2^{key_bits+1})`; both `key'_qi` and `2 · k_qi − lt_q(i)` lie in `(−2^23, 2^23)`, so by Lemma 0 they are equal as integers. Parity then separates the two cases: for `i < j_q`, `lt = 1`, `key' = 2k − 1` is odd and `≥ 0`, so `k_qi ≥ 1`, i.e. `x_qi < c_q`; for `i ≥ j_q`, `lt = 0`, `key' = 2k` is even and `≥ 0`, so `k_qi ≥ 0`, i.e. `x_qi ≤ c_q`. With `c_q = x_{q, j_q}`, `c_q` is the maximum and `j_q` the smallest position attaining it. In both cases `Exp2[key'] = Exp[⌈key'/2⌉] = Exp[k_qi]`, so `e_qi` is pinned exactly as today. Uniqueness (SP-3): given the row, `j_q` (the minimum argmax) is unique, hence the chunks; `Kread` is pinned by (b); `m` is pinned by the lookup multiset because the table keys are distinct; `c_q` by (c); `e_qi` by (d). Ties change nothing: the tie-break selects the first maximum and every later tie has `key' = 0`. ∎

Verifier side (SP-7): the range of `key'` is derived from public data alone, `|x| < 2^21` from range analysis, `|c_q| ≤ 128 · 127 · 128 < 2^21` from `Kread` being INT8 by table membership, `lt ∈ {0, 1}` from (a); the verifier never trusts a prover-declared range.

**Per-row count, E0 (own count, script in the session scratchpad; the experiment commits it).** Per (query row, head), with `oh = C · S^{1/C}`: new committed elements `oh + 128 (Kread) + 1/16 (m, `S` per KV head over `16 S` rows)`; LogUp leaves `128` (lookup side) `+ 128/16 = 8` (table side: `S × 128` entries per (layer, KV head) over `16 S` rows); sumcheck terms `128` (read zerocheck) `+ oh` (booleanity) `+ oh` (sum-one) `+ oh` (`lt` sumcheck) `+ oh` (causal `lt_q(q)`). Removed: `S/2` product-tree leaves on average (causal). At 16K, `C = 2`: 384 commitments, 136 leaves, 1,152 terms against 8,192 leaves. The generation pass's figure of 256 leaves per row counted the table side once per head; the shared table makes it 8.

## Why it could work

- **The lever is large under the repriced profile.** `c_π = 73` ps per leaf ([EXP-0006](../experiments/EXP-0006-product-leaf-cost/README.md): 25.5 `Fp` multiplications, 6 `mul_small(7)` and 63 additions per leaf, predicting the production forest prover within 2% on an Apple M4 Max; translated to the H100 integer pipeline at the 60% utilization of [VYTA25]; interval `[45, 117]` ps; E0 fitted to E1, primary). At 73 ps the product tree is 19.0% of `μ(16K)` and 20.9% of `μ(128K)` (E0, `counted` sensitivity table).
- **The replacement is per row, not per score.** At 16K the new relations cost `384 × 94 + 136 × 101 + 1,152 × 36.5` ps `≈ 92` ns per row (E0, `counted` unit costs; a level-shaped degree-3 sumcheck term is priced at half a product leaf because EXP-0006's tree costs twice its leaf level, E0 derived), that is 11.2 ps per score at `S/2 = 8,192` scores per row, 1.2 ps at 128K, 29.9 ps at 4K and 89.5 ps at 1K (a loss there). Pricing every sumcheck term at the full 73 ps moves the 16K figure to 16.3 ps (E0).
- **The shape is production practice.** Twist and Shout prove reads of a committed memory with `d` committed one-hot chunks per read and sumchecks instead of grand products ([ST25], primary, abstract; [JoltDocs26], [Chugh26], secondary); Lasso's `c` chunks of size `n^{1/c}` are the same decomposition ([STW23], primary). What made one-hot too expensive for Tessera's *lookups* (SUR-0002 Q2: 64–768 committed Booleans per lookup under a hash-based commitment that charges per element, [DBK+26]) does not apply here: there is one one-hot per *row*, not per score, and its `2√S` entries are amortized over `S/2` scores.
- **LogUp over committed values with committed multiplicities is RFC-0008's own relation** ([Hab22], [PH23], primary): values and multiplicities are committed advice today; only the table's value column becoming committed is new, and it is an activation (`k^{rot}`) the schedule already commits and opens. SUR-0002 [E0-this] prices a lookup at 101 ps in the `counted` profile; the table side here is `1/16` of a lookup per read because the KV head's keys serve 16 query heads (RFC-0005, primary).
- **Uniqueness under ties costs nothing per score** by living in the lookup key: the `Exp2` table has `2^{key_bits+1}` rows, amortized over `2.2 × 10^12` lookups per 16K proof unit, and its structured evaluation is unchanged (own construction, E0; Lemma 5′ above). RFC-0009's `Argmax` gadget already uses the same `lt` trick for the vocabulary (`g_v = m − ℓ_v − lt_v`, Lemma 9), at degree 1 because its one-hot is unchunked.
- **The "Reopens if" condition is met in count** ([baseline.md §7](../baseline.md#7-already-rejected): "a certificate cheaper than one product leaf per score with a uniqueness proof"): 11.2 ps against 73 ps at 16K with Lemma 5′ (E0).

## Expected gain

Baseline `counted` profile (`commits_per_token = lookups_per_token = 28,190,672`, `c_c` 94, `c_ℓ` 101, `c_π` 73 ps).

## Prior rejection check

Checked against [baseline.md §7](../baseline.md#7-already-rejected) and the Alternatives Considered of RFC-0009 and RFC-0008:

- **RFC-0009 Alternatives Considered 3**, "row maximum by committed one-hot index per row": rejected because "a one-hot entry costs a commitment (30 ps) where a product-tree leaf costs 12 ps, and the one-hot needs its own booleanity check". That alternative is an unchunked one-hot of `S` entries per row, one commitment per score. New: the chunked one-hot has `C · S^{1/C}` entries per row (256 at 16K against 16,384), so no per-score commitment exists, and the booleanity check is `oh` terms per row, not per score; and the `counted` repricing (`c_π` 12 → 73 ps, EXP-0006) turns the ratio the rejection rested on. Alternative 3 also never addressed uniqueness under ties; Lemma 5′ does, at no per-score cost.
- **RFC-0009 Alternatives Considered 6**, "embedding by lookup into a committed table": rejected because "LogUp over a committed 2^31-row table requires opening the table's commitment at the fraction tree's final point". New: the table here is `k^{rot}`, an activation the schedule already commits and opens, with `S × 128` rows per (layer, KV head), and the claim at the fraction tree's final point is one claim on a stacked tensor, batched as RFC-0010 batches claims; the objection reduces to at most one extra opening group (kill criterion 2), not a `2^31`-row table nobody opens.
- **RFC-0008 non-goal** "tables whose contents are committed rather than public" and **Alternatives Considered 1** (one-hot lookups: several committed chunks per lookup). New: the non-goal is a scoping decision with no soundness argument against it, and SUR-0002 Q2 records the per-lookup cost that justified it; here the one-hot is per row and the committed table is read 16 times per entry, which is the regime where the per-read cost is small. The separation principle [Jo26] is not engaged: no table structure is exploited to lower a per-lookup cost; the count per score is what changes.
- **SUR-0004 Q3** ("a one-hot or a per-row LogUp membership costs a commitment or a fraction-tree leaf per score, 30–40 ps against 12 ps") priced the unchunked one-hot and a per-score membership `(q, 0) ∈ {(q, k_qi)}`; neither is this mechanism, which reads 128 values per row instead of testing `S/2` keys.
- **[baseline.md §7](../baseline.md#7-already-rejected)** row "two-table softmax bracket; tolerance-band softmax; one-hot row maximum; ...": its "Reopens if" is "a certificate cheaper than one product leaf per score with a uniqueness proof", met in count here (E0).

Not "None": Alternatives 3 and 6 of RFC-0009 and the RFC-0008 non-goal cover the parts; what is new is the chunking, the shared committed activation as the table, the tie-break in the key, and the repriced `c_π`.

## Kill criterion

The RFC-0020 v0.1 gate measures `c_π` at or below about 20 ps while `c_c` and `c_ℓ` stay near their assumed values: the saving is then under 5% of `μ(16K)` and negative below 4K, not worth a tier-A RFC. Independently fatal: (2) the `k^{rot}` table claim cannot be batched to the leaf stage's existing point and each KV head's table needs its own opening group (a 64 MB combined row each, up to 1,008 per proof); (3) a soundness reading finds a second witness for the committed-table LogUp with prover-committed multiplicities (for example a tuple collision across `(i, d)` keys), or finds that `lt`'s degree exceeds 7 once `γ`-batching and masking are included; (4) the lemma-exhaustion test finds a passing witness other than `(max, min argmax)`.

## Cheapest experiment

Hypothesis (pre-registered here): (H1) the exact per-(layer, KV head) count of commitments, LogUp leaves, sumcheck terms and table rows at 1K / 4K / 16K / 128K, against `S(S+1)/2` product leaves, gives a per-score equivalent below 12 ps at 16K and below 2 ps at 128K under the `counted` unit costs, and above 73 ps at 1K (E0); (H2) Lemma 5′ holds by exhaustion: on rows of 3–4 scores in `[−8, 8]`, over all `c_q`, all chunk assignments (`C = 2`, chunks of 2), all `Kread`, all `lt` values and all `key'` in range, including tied rows and `j_q > q`, exactly one witness passes relations (a)–(d) and it is `(max, min argmax)` (E1).

Method: (1) commit the count as `research/experiments/EXP-NNNN-argmax-read-certificate/count.py` (SPDX header, `-I` clean), each RFC rule as a line, printing the table above and the cost-model commands; (2) `lemma.py`, the exhaustive check of H2 over the integers, with the field relations evaluated over `F65537` as well so that a wrap-based second witness would show (RFC-0009 'Testing Strategy' pattern); (3) optional: a toy committed-table LogUp read in `tv-*`-style arithmetic over `F65537` to measure the empirical false-accept rate of one random-`α` trial against `(N + T)/|F|` (RFC-0008 'Testing Strategy'). Experiment update 2026-10-19: [EXP-0016](../experiments/EXP-0016-argmax-read-lemma/README.md) is `done: refuted`; the literal idea is `rejected` by research rule1. The fully scoped local variant has exactly one witness on348,823 causal prefixes of3/4-score rows in [-8,8], plus1,458 d2 dot-prefix cases (E0). But complete merged batches admit four wrong rows each under cross-layer and KV-head swaps: every read dimension is present, m is shared per position, all rational identities are balanced and all reciprocal brackets pass. In a wrong row, c is one above the true maximum, both exponentials are6 instead of16, and s12/R21/a4/b7 pass. The current product certificate has root1 and rejects; this is a proposed-replacement defect, not a production exploit. Full namespace tags leave lookup tuples absent from the table support, so arbitrary multiplicity changes cannot fix the repair-control rejection. Direct Goldilocks d4/four-position lifts satisfy current sigma/context validation, including709c37c/#388; no complete model or proof is claimed.

The experiment also resolves two textual obligations: ceil(key/2) is not key>>1 at odd keys (6 versus16 at key1), and the top odd doubled key needs an explicit zero-tail completion. Current RFC-0030 masks every padded score and RFC-0035 pins padded c/R; new chunks/Kread also need a coherent psi/public-padding rule. Goldilocks packing must be injective across every merged layer/KV/position/dimension, with a checked total belowP or separate tuple coordinates. The405B shape passes that packing bound, while a syntactic larger shape aliases; full resource acceptance of the latter is not asserted. The old SP-3 argument and priority1.21 are therefore superseded, confidence0.3→1.0 in this scoped counterexample. A corrected design needs a newly scoped theorem and superseding RFC before any cost or H100 work; finite local success is not that theorem.
