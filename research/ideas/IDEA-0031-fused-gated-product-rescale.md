## Mechanism

Setting ([RFC-0005 'Integer semantics'](../../docs/rfcs/RFC-0005-integer-model.md#integer-semantics), ✓ verified 2026-10-17). In the `servable` profile the MLP block computes `y = rq(res · ρ, r_n)` (INT8, `d = 16,384`), `g = W_gate y`, `u = W_up y` (accumulators `< 2^29` by the public bound `127 · fan_in · max|y| = 127 · 16,384 · 128 < 2^28`, stated `< 2^29`), `a = T_silu[g]` (INT8), then the product row `u8 = rq(u, r_u, −128, 127)`, `h = rq(a · u8, r_h, −128, 127)`, `acc = W_down h`. Each of `u8`, `a`, `h` is a committed INT8 tensor of 53,248 elements per layer per token with one `Requant1` (or `TableMap`) lookup each ([RFC-0006 'Gadget selection'](../../docs/rfcs/RFC-0006-compiler-ir.md#gadget-selection): `b ≤ B_max = 32`, 1 commitment, 1 lookup). The `h` key `a · u8` is already a degree-2 product of two committed values with `|a · u8| ≤ 2^14`, `b = 15`.

What changes:

1. **Certificate, once per model** (with the weight commitment of RFC-0012). `tessera-quant` enforces `‖w_row‖₂ ≤ 2^k` for every output row of `W_up`, with a public per-tensor `k` in the claim list (a power-of-two bound chosen by the quantizer, like the four shift classes today). The prover proves it per row by the four-squares relation of SUR-0009 [E0-this] (c), [LNP22]'s `ℓ2` mechanism transcribed to a sumcheck: `2^{2k} − Σ_i w_i² = s_1² + s_2² + s_3² + s_4²` with four committed scalars per row, each range-checked `s_j ∈ [0, 2^{k+1})`; every term is `< 2^{2k+2} ≤ 2^28 ≪ P` for `k ≤ 13`, so the relation is exact over the integers (RFC-0009 Lemma 0 applies) and Lagrange's theorem guarantees the honest prover can always find the four squares. Cost: `1.99×10^7` rows for 405B (`W_up` is `53,248 × 16,384` per layer, 126 layers: `6.7×10^6` rows; the figure covers the other norm-fed tensors too, SUR-0009 Q2), `7.9×10^7` commitments, proven once and cached by verifiers (E0, primary: SUR-0009 Synthesis Q2).
2. **Relational fact, zero cost.** `RsqrtRow` already proves `ρ² u ≤ N = d · 2^{2κ}` with `u = Σ_i res_i² + e` ([RFC-0009 `RsqrtRow`](../../docs/rfcs/RFC-0009-gadgets.md#rsqrtrow), Lemma 7 via Lemma 4). Hence `Σ_i (ρ · res_i)² ≤ N`, and since `|y_i| ≤ |ρ · res_i| / 2^{r_n} + 1/2` (round half up, then clamp, which only shrinks), the triangle inequality gives `‖y‖₂ ≤ 2^{κ − r_n} √d + √d / 2`. RFC-0006 'Range analysis' lists it beside the `SoftmaxRow` fact (and beside IDEA-0011's `max_i |ρ · res_i| ≤ 2^κ ⌈√d⌉`, which is the `ℓ∞` form of the same bracket).
3. **Range analysis.** `MatMulWeight`'s transfer for `W_up` uses Cauchy–Schwarz, `|u_j| ≤ ‖w_j‖₂ · ‖y‖₂ ≤ 2^k · (2^{κ − r_n} √d + √d / 2)`, instead of `127 · fan_in · max|y|`. Both inputs are public (`k`, `κ`, `r_n`, `d`), so the verifier re-derives the bound (INV-IR-5, SP-7). Exact arithmetic at `d = 16,384` (E0, primary: scratchpad script 2026-10-17): the fused key below fits `b = 32` iff `2^k · (2^{κ − r_n} + 1/2) · 2^7 · 2^7 < 2^31`, i.e. **`k + (κ − r_n) ≤ 16`**: `RMS(y) ≤ 32` (`r_n = 11`) with row RMS `≤ 16` (`k = 11`, `|u| ≤ 2^23.02`, `|a · u| ≤ 2^30.02`), or `RMS(y) ≤ 16` (`r_n = 12`) with row RMS `≤ 32` (`k = 12`, `|u| ≤ 2^23.04`). The generation pass's "row RMS ≤ 32 at RMS(y) = 32" (`k = 12`, `r_n = 11`) gives `|u| ≤ 2^24.02` and `|a · u| ≤ 2^31.02`, one bit too wide: it needs `b = 33` and the fused rescale would split. The target is therefore `|u| < 2^23` after the `√d / 2` term, not `2^24`.
4. **RFC-0005 semantics.** The `servable` product row becomes `h = rq(a · u, r_u + r_h, −128, 127)`, `acc = W_down h`: one rounding instead of two, no intermediate saturation at `u8`. `D` changes (protocol-affecting). The `minimal` profile is untouched.
5. **Gadget.** `Requant1` with the degree-2 virtual key `z = a · u` (`a` the committed SiLU output, `u` the up-projection sumcheck claim, both already in the relation set: today's `h` key `a · u8` has the same shape), `|z| < 2^31` under the certificate, signed width `b = 32 = B_max`, table `Requant{b = 32, classes = 1, r_u + r_h, −128, 127}` of `2^32` rows. The one-class condition: `pack(c, z) = (z + 2^{b−1}) + 2^b · c` ([RFC-0009 `Requant1`](../../docs/rfcs/RFC-0009-gadgets.md#requant1)) gives a table of `2^{b} · classes` rows, so at `b = 32` only one class fits `B_max` (IDEA-0011's observation (b)). `W_up`'s per-channel shift classes ([RFC-0005 'Scale policy'](../../docs/rfcs/RFC-0005-integer-model.md#scale-policy): up to 4 consecutive weight-exponent classes per tensor) must therefore be absorbed: either `W_up` at one per-tensor power-of-two weight scale (1 class; the quantizer raises every channel to the window's top exponent, which costs weight resolution on the smaller channels), or 2 classes with `|u| < 2^22` after the margin (`k + (κ − r_n) ≤ 15`), or 4 classes with `|u| < 2^21` (`k + (κ − r_n) ≤ 14`, RMS products of 16 or less; not reachable by the certificate alone at RMS(y) = 32).
6. **Serving** (`servable` S1 and S2 of [RFC-0005 'Profiles'](../../docs/rfcs/RFC-0005-integer-model.md#profiles) hold): `h` stays INT8, the INT8 tensor-core GEMM for `W_down` is unchanged, and the fused SwiGLU epilogue computes `a · u` in INT32 (`|a · u| < 2^31` by the certificate: S2 holds for the product too), then shifts by `r_u + r_h` with round-half-up and clamps. One fewer rounding kernel per MLP.
7. **Verifier** (`tv-*`): re-derives `|u| ≤ 2^k (2^{κ − r_n} √d + √d / 2)` from the public `k`, `κ`, `r_n`, `d` (SP-7, INV-IR-5), rejects a claim list whose `k` makes the fused key wider than `B_max` (`ERR-COMPILE-RANGE` on the prover side, a claim-list validation error on the verifier side), checks the four-squares relation and the four range lookups per `W_up` row at the weight commitment's opening, and generates the fused `Requant{b = 32}` table from its definition (RFC-0008 structured evaluation: the non-constant core is still the 256-value output range, so verification time does not grow with `b`).

Net per layer per token (E0, primary: arithmetic on the RFC-0005 tensor list): `servable` with every split 326,656 → 273,408 committed elements and lookups (−53,248, −16.3%); per token at 126 layers `4.116×10^7` → `3.445×10^7`. With [IDEA-0011](IDEA-0011-rsqrt-fact-norm-key.md) (−32,768) and a RoPE route (−17,408, SUR-0009 seed 3) as well: 223,232, 1.4% above the corrected `minimal` figure of 220,160 that the cost model carries today.

## Why it could work

- **Count** (E0, primary: [RFC-0005 'Integer semantics'](../../docs/rfcs/RFC-0005-integer-model.md#integer-semantics) and ['Profiles'](../../docs/rfcs/RFC-0005-integer-model.md#profiles), [RFC-0006 'Gadget selection'](../../docs/rfcs/RFC-0006-compiler-ir.md#gadget-selection), own arithmetic 2026-10-17). The default `servable` profile costs 260,096 per layer per token before splits (SUR-0009 [E0-this] (b)), and 326,656 with every split the selection rule forces: the two norms 32,768 (keys `< 2^37`), RoPE 17,408 (`< 2^44`), and the attention-output rescale `o8` 16,384, which SUR-0009's 310,272 omits (`o < 2^39` using `R_q s_q ≤ 2^{2σ}`, signed width 40 > `B_max`, hence `RequantSplit` with `s = 8`; ✓ verified from the RFC-0005 range column). `u8` is 53,248 of those: the single largest removable item, one of the three equal tables (`u8`, `a`, `h`) that are 61% of `servable` before splits. The saving is a count reduction, independent of the unit-cost uncertainty (`c_c`, `c_ℓ`) that dominates most ideas in this directory.
- **Mechanism, each piece primary.** The degree-2 virtual key already exists (`h`'s key `a · u8`, RFC-0009 `Requant1`; E0, primary). The relational-fact path exists and is used once (RFC-0006 'Range analysis', "v1 has one"; E0, primary). `RsqrtRow`'s bracket is a proof obligation today (RFC-0009 Lemma 7; E0, primary), so the `‖y‖₂` fact is free. The four-squares `ℓ2` certificate is [LNP22]'s mechanism (E0, primary for the lattice original; the sumcheck transcription is SUR-0009 [E0-this] (c), own work, unverified beyond the exactness bound checked here).
- **A per-row weight-norm bound is public, input-independent and enforceable at PTQ time.** A2Q+ ([CPPU24]) and AXE ([CFGZS25]) constrain `‖w‖₁` per row so that a 16-bit accumulator cannot overflow, at 0.3–0.6 perplexity points on Llama3 8B at W4A4 (E1 on their GPUs, primary, as read for SUR-0009); Tessera needs only 4–5 bits off a 28-bit worst case at W8A8, a far weaker constraint. [CFGZS25] also rejects empirical overflow estimates on the same SP-7 ground RFC-0006 Alternative 4 does.
- **Fidelity direction.** A single rounding `rq(a · u, r_u + r_h)` is, pointwise, at least as close to the real product as the two-step form through a saturating INT8 `u8`: checked exactly over the integers on 10^6 seeded cases (`a ∈ [−128, 127]`, `|u| < 2^24`, `r_u ∈ [1, 20]`, `r_h ∈ [1, 12]`): the fused form is never farther from the clamped exact value and strictly closer in 46.8% of cases; `max |a · u| = 2.147×10^9 < 2^31` with no violation (E0, primary: scratchpad `fused_check.py`, 2026-10-17). The analytic reason is the nested-floor identity of RFC-0009 Lemma 2 plus the `|a| / 2` error the intermediate rounding injects. I-LLM treats the SwiGLU product as one activation–activation pair rather than two rescales ([HCY+24], E1, primary). Power-of-two weight scales cost ≤ 0.5% perplexity at ≤ 14B ([ChenTR26], E1, primary) and SmoothQuant's W8A8 recipe quantizes weights per tensor up to 530B ([XLSLLHD23], E1, primary paper; the per-tensor granularity is recalled, not re-read today: secondary), which is the 1-class condition this idea needs for `W_up`.
- **Cost model** (E0, primary: `research/tools/cost_model.py`, run 2026-10-17): `servable` with all splits `μ(1K)` 10.4 corrected / 21.6 counted; after fusion 9.6 / 19.4 (tables below).

## Security gate

| Property | Effect | Pass |
|---|---|---|
| Soundness bits (G-4, RFC-0014) | Unchanged. The fused `Requant1` lookup pins `h` given the key `a · u`; the key is a true integer only under `\|u\| < 2^23`, which the verifier derives from the certificate and the `RsqrtRow` bracket, not from the prover: the four-squares relation (exact over the integers, every term `< 2^28 ≪ P`, Lemma 0) with four range lookups per row is checked at the weight commitment's opening, and `‖y‖₂` follows from `ρ² u ≤ N`, already proven exactly (Lemma 4). A prover whose `W_up` rows violate `‖w‖₂ ≤ 2^k` fails the certificate, so completeness, not soundness, is what the quantizer guarantees. The degree-2 key raises no sumcheck degree beyond today's `a · u8`. No challenge, label or absorption order changes (INV-FS-1..4). The certificate's own soundness is that of the lookup and sumcheck arguments it reuses (RFC-0014 bounds), with one new relation per `W_up` row absorbed with the weight commitment. | pass |
| Uniqueness upstream of the logits (SP-3, RFC-0009 Lemma 0) | The fused table is a function of its key (Lemma 1), so exactly one `h` passes given `(a, u)`; `u` is pinned by the `W_up` sumcheck claim and `a` by its own lookup. One fewer committed value (`u8`) per MLP element, so one fewer value for INV-IR-3 to cover. The four square-root scalars per `W_up` row are *not* unique (a number has many four-squares decompositions), but they are advice downstream of nothing: they witness an inequality on the weights, never feed `D`, and any valid decomposition proves the same bound, so SP-3 (uniqueness of every value upstream of the logits) is unaffected; the note states this explicitly for the soundness refuter. | pass |
| Zero knowledge (G-5, RFC-0013) | `k` is a public per-tensor design constant chosen by the quantizer as a power of two (like the four shift classes today), met by every honest prover for every input, so it leaks nothing input-dependent (RFC-0006 Alternative 4's honest-prover-failure hazard does not arise). It reveals an upper bound on `W_up`'s row norms, one number per tensor, which a per-tensor pot weight scale already implies in order of magnitude; whether that one number per tensor is acceptable under the treaty setting's weight hiding (RFC-0012, RFC-0013) is the question the zk refuter must answer. The four committed square roots per row are hidden like other weight-side advice (RFC-0013 masking); one fewer committed activation per element. | unknown |
| Verifier independence (SP-6) | The verifier implements the certificate check (four-squares relation, four range lookups per row at the opening), the two public range derivations and the fused table generator from the specification; no prover code or data is trusted (SP-7: no prover-declared range). Every table is still a piecewise function with a 256-value core (RFC-0008). | pass |
| Post-quantum (hash-based commitments) | Unchanged: the certificate is committed under the same hash-based weight commitment. | pass |

Caveats, both pre-registered here: removing `u8`'s saturation changes `D` (protocol-affecting; superseding RFC), and the serving kernel must compute `rq(a · u, r_u + r_h)` bit-exactly (RISK-3: INT32 suffices under the certificate; the rounding is a shift, so no new numeric hazard).

## Prior rejection check

- [RFC-0006 Alternatives Considered](../../docs/rfcs/RFC-0006-compiler-ir.md#alternatives-considered) 1 rejects a *search* over requantization placements for v1 because placement changes `D` and must be co-optimized with fidelity; [RFC-0006 Drawbacks](../../docs/rfcs/RFC-0006-compiler-ir.md#drawbacks) names the unexplored reductions. This is one fixed placement change that is strictly more precise (single rounding, no intermediate saturation; E0, checked above), so the fidelity co-design reduces to one gate run of `tessera-quant eval`; what is new is the certificate that makes the fused key fit `B_max`, which no template could assume.
- RFC-0006 Alternative 4 (calibration-based ranges) is respected: the bound is a public weight-side constraint that holds for every input, as [CFGZS25] demands and SP-7 requires. Alternative 5 (wrap tracking) is unrelated.
- [RFC-0005 Alternatives Considered](../../docs/rfcs/RFC-0005-integer-model.md#alternatives-considered) 2 (per-token scales) and 3 (`affine` everywhere) are untouched; Alternative 5 (one profile only) is respected: `minimal` is unchanged, `servable` keeps S1–S3.
- RFC-0009 Alternatives (rsqrt by table, Newton) and the matching row of [baseline.md §7](../baseline.md#7-already-rejected): unrelated; `RsqrtRow` is unchanged. Baseline §7 has no row on placement, range facts or weight certificates; [baseline §6](../baseline.md#6-levers-which-technique-class-moves-which-term) lists "range analysis, rescale placement" as a lever on `C_lin`, `K_lin` without a rejection.
- Overlap with sibling ideas: [IDEA-0011](IDEA-0011-rsqrt-fact-norm-key.md) uses the `ℓ∞` form of the same bracket on a different tensor (the norm key); [IDEA-0023](IDEA-0023-dilation-shared-requant-tables.md) prices table-side leaves. Neither covers the product row. "None" after the check.

## Kill criterion

Any one of: (a) `tessera-quant` cannot hold `W_up`'s rows at `‖w‖₂ ≤ 2^k` with `k + (κ − r_n) ≤ 16` under a 1-class per-tensor power-of-two scale (or `≤ 15` with 2 classes) without failing the [RFC-0005 gates](../../docs/rfcs/RFC-0005-integer-model.md#fidelity-evaluation) (perplexity ratio ≤ 1.03, top-1 ≥ 0.93 at 70B and 405B), especially after SmoothQuant migration inflates rows on outlier channels; (b) the v0.2 commitment report shows `u8` is not 53,248 committed elements per layer per token, or that the `servable` product row is already `Requant1`-free some other way; (c) `B_max` is reduced to 30 at OQ-0006-1 (the fused `b = 32` key would then split and the gain vanishes; at `B_max = 32` the `2^32`-row table's side cost is dominated by the saving by about 100×, E0); (d) the serving kernel cannot reproduce `rq(a · u, r_u + r_h)` bit-exactly on INT8 tensor cores (RISK-3).

## Cheapest experiment

Hypothesis: with a public per-row bound `‖w_row‖₂ ≤ 2^k` on `W_up` and the `‖y‖₂` fact from `RsqrtRow`, the fused key `a · u` is a true integer of signed width `≤ 32` whenever `k + (κ − r_n) ≤ 16` at `d = 16,384`; the fused rounding is pointwise at least as close to the real product as the two-step form; and the `servable` count falls 326,656 → 273,408 per layer per token.

Method (E0, effort `s`, one day; needs no hardware beyond a laptop): a seeded exact-integer script (Python big integers) under `research/experiments/EXP-NNNN-fused-gated-product/` with its pre-registered criterion, that (i) reproduces the `servable` counts 260,096 / 326,656 / 273,408 per layer per token from RFC-0005's tensor list and RFC-0006's selection rule; (ii) checks on 10^6 synthetic `(a, u, r_u, r_h)` cases that `rq(a · u, r_u + r_h)` is never farther from the clamped exact product than `rq(a · rq(u, r_u), r_h)` and that `|a · u| < 2^31` whenever `|u| < 2^24` (the scratchpad version of this check already passed: 0 worse, 467,523 strictly better, no violation); (iii) checks the four-squares relation's exactness bounds (`k ≤ 13`: every term `< 2^28`) with a Rabin–Shallit decomposition on synthetic INT8 rows at RMS 8–64, and the `‖y‖₂` fact on IDEA-0011's 7,590 synthetic residual rows; (iv) runs the four cost-model scenarios above and the table-side leaf arithmetic. An adversarial check belongs with it: a `W_up` row with `‖w‖₂ > 2^k` must have no four-squares witness (`2^{2k} − Σ w_i² < 0`, and the range lookups reject any `s_j` that would make a negative sum), stated as the exact rejection.

The fidelity half (does a 1-class `W_up` with row norms at `2^k` pass the gates at 70B and 405B after migration) is E2-level work: a BF16 reference and real weights, outside `research/` rule 6 (no model weights here). It stays unknown until `tessera-quant` exists and runs on a GPU with the model; the E0 experiment can bound it only by stating which `(k, r_n)` pairs the certificate admits.
